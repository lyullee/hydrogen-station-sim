# 실측 기반 재충전 동특성 보정

이 문서는 소유자 관리 실측 자료를 원자료·설비명·태그명·절대 시각 없이 수소충전소 디지털 트윈의 **재충전 재기동 대기시간** 후보로 평가하는 절차를 설명한다. 후보값은 다중 기록 시간순 검증을 통과한 경우에만 운전 설정에 적용할 수 있다.

## 적용 범위

실측 압축기 부하 상태와 일반화한 중·고압 저장영역 압력을 같은 시간축으로 비교해 다음 값만 산출한다.

- 압축기 OFF 후 다음 ON까지의 완료된 대기 구간
- 압축기 가동·비가동 중 저장영역 압력 변화율
- 기동에서 정지까지의 압력 이력 폭

현재 승인된 비식별 집계는 **8개 운전 기록, 학습 457,405개 표본, 검증 196,037개 표본**을 사용한다. 각 기록의 앞 70%에서 후보값을 정하고, 뒤 30%의 완료된 OFF→ON 구간으로 일반화 여부를 점검했다.

- 학습 구간 후보 최소 재기동 대기시간: **290.0 s**
- 학습 구간 완료 OFF→ON 구간: **89개**
- 검증 구간 완료 OFF→ON 구간: **32개**
- 검증 구간 최단 OFF→ON 시간: **176.0 s**

검증 구간 최단값이 후보값보다 짧으므로 다중 기록 검증 결과는 **FAIL**이다. 기존 한 기록에서 산출한 265.2 s 결과는 감사 추적용으로만 보존하며 런타임 적용 근거로 사용하지 않는다. 시뮬레이터는 현재 기준 제어값을 사용하고, 실측 재충전 대기시간 선택 기능은 잠겨 있다.

## 적용하지 않는 항목

이 자료에는 동기화된 차량 탱크 압력·온도, 노즐 질량유량, 차량 통신/충전 프로토콜 상태가 포함되지 않는다. 따라서 다음에는 사용하지 않는다.

- 압축기 정격 용량 또는 노즐 유량 보정
- 차량 충전 종료 예측이나 SAE J2601 적합성 주장
- 용기 설계압, 안전밸브 설정, ESD 설정, 안전거리의 결정
- 사고 빈도·개인위험도 또는 현장 안전인증
- 전체 station-to-vehicle 루프의 정확도 주장

이 경계는 전체 충전루프를 하나의 계수로 맞추어 과도한 주장을 하는 것을 막는다. 차량측 검증은 독립된 공개 차량 충전 자료로 계속 수행하고, 실제 충전소 자료는 저장·압축기측 동특성에만 쓴다.

## 압력 여유폭과 시간 대기의 분리

재충전 제어에서 두 값은 구분한다.

- **재기동 압력 여유폭**은 압축기 정지 압력에서 다음 기동 압력까지의 하강폭이다. 확인된 압축기 상태와 해당 저장영역 압력을 연결하면 직접 관찰할 수 있다.
- **최소 시간 대기**는 정지 후 강제로 기다리는 시간이다. 원자료의 OFF 시간에는 일반적인 수요 대기도 포함되므로 하드웨어 냉각 대기시간으로 그대로 해석할 수 없다.

8개 기록의 압력 하강 진단에서는 고압 단계의 완료 재기동 124건이 확인됐고, 정지-재기동 압력 하강폭 중앙값은 4.555 MPa였다. 시뮬레이터는 이를 한 자리로 반올림한 **4.5 MPa**를 고압 뱅크 개발 기본값으로 사용한다. 반면 290 s 시간 대기 후보는 시간순 검증에 실패했으므로 계속 비활성화한다. 근거 집계는 `research/confidential_station_recharge_pressure_drop_diagnostic_2026_10_08.json`에 있다.

## 현재 실행 상태

리모콘의 **운전 설정 → 실측 보정 · 검증 상태**에는 다중 기록 검증 미통과 상태가 표시된다. 재충전 대기시간 체크 상자는 비활성화되며, API 기본값도 `false`이다. API에 `process_settings.measured_station_dynamics_calibration: true`를 직접 보내더라도 검증된 프로필 로더가 결과를 거부하므로 작업 상태에는 `unavailable`이 기록되고 기준 제어로 실행된다.

LLM 근거 봉투에는 실패 결과 자체를 남긴다. 8개 기록 수, 후보 290.0 s, 검증 최단 176.0 s, `runtime_parameter_application=false`와 차단 사유를 함께 제공한다. 따라서 SAGA는 후보값을 적용값으로 설명할 수 없다.

다중 기록 검증을 통과한 새 근거가 생기면 그때만 프로필 로더와 UI 잠금을 해제한다. 이미 적분을 시작한 운전에는 프로필을 중간 적용하지 않는다.

## 재생성 및 검토

제한된 환경에서 다음 스크립트를 실행한다.

```powershell
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe scripts\calibrate_confidential_station_recharge_dynamics.py `
  --input <restricted-trace-or-folder> `
  --mapping <custodian-mapping.json> `
  --output <approved-aggregate.json> `
  --compressor-state-role <approved-role> `
  --active-state <approved-active-value> `
  --bank-role <approved-pressure-role>=medium `
  --bank-role <approved-pressure-role>=high `
  --pressure-semantics-attested --state-semantics-attested `
  --temporal-holdout --calibration-fraction 0.70
```

스크립트는 원자료를 메모리에서만 읽으며 결과에 원시 행, 식별자, 절대 시각, 경로, 태그명, 제조사·모델을 포함하지 않는다. 런타임은 다음 조건을 모두 만족한 집계만 읽는다.

1. 압력 역할·단위와 압축기 상태 의미를 데이터 관리자가 확인한다.
2. 시간 순서 holdout에 최소 3개의 완료 OFF→ON 구간이 있다.
3. holdout의 최단 대기시간이 앞 구간에서 정한 대기시간보다 짧지 않다.
4. 경고·결측·비단조 시간 문제가 없다.
5. 기본 모델은 변경하지 않고 선택 적용으로만 사용한다.

현재 집계와 생성 스크립트는 비식별 근거 형식만 저장한다. 원자료와 제한 매핑 파일은 저장소에 추가하거나 Git으로 추적하지 않는다. 생성 결과가 검증에 실패하면 스크립트는 `runtime_parameter_application=false`와 차단 사유를 기록하고, 런타임 로더는 해당 결과를 적용하지 않는다.
