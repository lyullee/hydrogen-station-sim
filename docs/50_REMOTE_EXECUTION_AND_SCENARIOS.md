# 리모콘 실행 복구와 사고 시나리오 확장

2026-09-25

## 수정한 실행 문제

- 브라우저 숫자 입력의 `min`·`step` 조합이 기본 UA 1,000 W/K와 응답시간 30초를 유효하지 않은 값으로 판정해 제출을 차단했다. 숫자 입력의 step을 `any`로 바꾸고 범위와 필수 입력 검증은 유지했다.
- 입력 오류, 사고 시작/종료 시각 오류, 서버 연결 오류, 계산 실패를 고정된 실행 영역에 표시한다.
- 연속 실행 중 폼 전체를 잠그던 동작을 제거했다. 다음 조건을 편집한 뒤 **정지 후 새 조건으로 실행**을 누르면 기존 실행의 정지 완료를 확인하고 새 초기 조건으로 실행한다. 실행 중인 물리 상태에 즉시 사고를 추가하는 기능은 아니다.
- 저장뱅크와 호스 열전달에서 미분 상태 객체의 잘못된 필드명 때문에 발생하던 AttributeError를 수정했다. 벽면의 온도 변화율에 열전달 항을 더하고 기존 에너지 수지로 내부 가스 온도에 반영한다.
- 리모콘에서 생성한 실행을 BroadcastChannel, storage, 동일 출처 opener 메시지로 메인 화면에 연결한다.

## 사고 라이브러리

`web/scenarios.json`은 `scripts/build_remote_scenarios.py`로 생성한다. 서버가 구현한 15개 FaultKind를 모두 노출한다.

| 분류 | 시나리오 수 | 예시 |
|---|---:|---|
| 누출 | 9 | 3개 저장뱅크, 양쪽 호스·차량, 압축기 연결부, 헤더 |
| 외부 화재 | 7 | 각 저장뱅크, 양쪽 호스·차량 |
| 압력 | 14 | 7개 지점의 상승·저하 |
| 가열·냉각 | 4 | 차량 가열, 호스 냉각 |
| 막힘·역류 | 6 | 호스·PCV 부분 막힘, 체크밸브 고장 |
| 설비 고장 | 8 | 밸브 고착, 예냉 저하·상실, 압축기 정지, ESD |
| 센서 진단 | 12 | 압력·온도·유량 센서 편향과 값 고정 |
| 복합 사고 | 8 | 누출 후 ESD, 동시 누출, 화재 후 지연 누출 등 |
| 합계 | **68** | 검색·분류·복수 추가·개별 수치 편집 가능 |

직접 구성에서는 모델에 연결된 센서 38개를 편향·고정 대상으로 선택할 수 있다. 선택 위치, 입력 단위, 시작/종료 시각 및 해당 사고에 필요한 항목만 표시한다.

## 모델 범위

- 누출은 질량과 에너지를 실제 공정 재고에서 차감한다. 외부 화재·가열·냉각은 열원 온도와 UA를 사용한다.
- 압축기 연결부와 헤더의 물리 교란은 현 모델의 고압뱅크 재고/상태를 공유한다. 독립적인 배관 체적 모델이 아니다.
- PCV·캐스케이드 밸브 고착과 예냉 성능 저하는 두 라인에 공통 적용한다. 부분 막힘은 라인별로 선택 가능하다.
- 체크밸브 고장은 역류를 허용한다. 역류 발생 여부는 실제 압력차에 따른다.
- 센서 편향·고정은 HAZOP 진단 신호에 적용하며 물리 공정값과 기존 안전 PLC 입력은 바꾸지 않는다.
- 화재 이후 지연 누출은 지정한 두 사고를 순서대로 주입한다. 자동 파손·점화·연소 전파를 예측하는 모델은 아니다.
- 가스검지 신호는 누출 기반 가상 대리값이며, 피해 영향은 기존 HyRAM 계산 연계를 이용한다.

## 검증 기록

- 사고 프리셋 입력·대상·모델 실행, HAZOP·누출·압력·연속 정지 관련 검사: 98개 통과 (`data/remote-scenario-validation.txt`).
- 저장뱅크 3개 및 양쪽 호스의 가열·냉각 시 벽면/가스 온도 방향성 검사: 10개 통과 (`data/remote-thermal-validation.txt`).
- `node --check web/remote.js`, `node --check web/dashboard.js` 통과.
- 브라우저: 정상 연속 운전 시작 → 운전 중 조건 편집 → 기존 실행 정지 완료 → 화재 실행. 저장뱅크 화재 25초 계산 완료. 압력 교란의 기본 응답시간 30초 입력·실행 완료. 종료 시각 오류 표시, 38개 센서 선택, 복합 사고 검색·추가 확인.
- 전체 **68개** 시나리오가 0~25초 계산을 완료했다. 각 기본 사고의 시작(5초), 지연 복합 사고(10초), 종료(20초) 및 종료 이후까지 유한한 공정 상태를 유지하는지 확인했다. `scripts/validate_remote_scenarios.py`로 수행했고 결과는 `data/remote-full-window-validation.json`에 저장했다. 이 검증은 공정·HAZOP 연계 검증이며 HyRAM 피해량의 정확도 검증은 포함하지 않는다.
- 실제 서버의 HyRAM native backend에서 2번 호스 누출 후 ESD 복합 사고를 리모콘으로 실행해 12초 계산 완료, 누적 누출 0.002467 kg, GD-2201 3.24 vol% 가상 신호와 ESD·HAZOP 표시를 확인했다.
- 최종 화면은 사고 주입 없는 연속 실행 `37c0d354a6ff4c6dad258a0f244ab071`에 연결했다. 리모콘에서 실행 정지 또는 새 조건으로 재실행할 수 있다.
