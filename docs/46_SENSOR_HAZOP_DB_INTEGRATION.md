# 센서 기반 HAZOP DB · 디지털 트윈 매핑 및 연동 검토

작성일: 2026-09-23. 대상: `hydrogen-station-sim` 현재 로컬 구현.

## 결론

기존 엑셀의 23개 노드, 82개 센서, 205개 규칙을 SQLite로 이관하고 디지털 트윈의 매 계산 주기에 연결했다. 사고 후보와 HyRAM 계산 상태를 웹 화면과 API에 표시하며 이벤트를 별도 SQLite에 저장한다. 원본 엑셀의 수치·문구·활성화 설정은 변경하지 않았다.

| 구분 | 결과 | 의미 |
|---|---:|---|
| 모델 상태 연결 | 28개 센서 | 공정 상태·유량 계산값 |
| 공유 계산값 연결 | 6개 센서 | 합산 유량 및 동일 유량의 별칭; 독립 계측 아님 |
| 공급 경계조건 연결 | 4개 센서 | 고정 공급 압력·온도; 트레일러 고갈을 관측하지 못함 |
| 미연결 | 44개 센서 | 입력 자체 없음 |
| 구조상 실행 가능 | 89 / 205개 규칙 | 신호식·모드 조건·필요 모델이 모두 지원됨 |
| 구조상 미지원 | 116 / 205개 규칙 | 센서, 상태 조건 또는 물리 모델 보완 필요 |
| 실제 현장 센서 연결 | 0개 | 현재 연결 대상은 시뮬레이션 |

89개는 경보 성능 검증 수가 아니다. 실행 중에는 비활성 운전 조건, 이력 수집, 값의 품질에 따라 INACTIVE·PENDING·UNKNOWN이 될 수 있다. 미지원 규칙도 운전 조건이 명백히 거짓이면 INACTIVE이므로 실시간 UNKNOWN 개수와 116은 일치하지 않는다.

## 구현한 연결

`원본 XLSX → 검증된 SQLite 정의 → 모델 신호/운전 상태 → 규칙 판정 → 사고 후보 그룹 → HyRAM 입력 대기/기존 계산 결과 연결 → 이벤트 SQLite + API + 화면`

- 정의 DB: `src/h2station/data/hazop.sqlite3`. 노드·센서·규칙·운전 상태·HyRAM 케이스·출처·누출 크기·입력·연동규약·매핑을 저장한다. `rule_conditions` 뷰로 숫자 임계값을 조회할 수 있다.
- 이벤트 DB: `data/hazop-events.sqlite3`. 실행별 정의 버전·원본 SHA256과 발생/복귀 이벤트, 판정값·임계값·의존 신호·모드 스냅샷을 저장한다. 전체 시계열 영구 보관 DB는 아니다.
- API 최종 결과 및 WebSocket 프레임에 `hazop`을 추가했다. 기존 실시간 프레임에서 누락됐던 2번 호스 압력·온도도 추가했다.
- MPa 절대압, °C, g/s, vol% H2로 판정한다. 단위·값·시각·품질을 검사하고 결측을 0으로 바꾸지 않는다. 시간축은 시뮬레이션 초이다.
- `>=`/`<=` 수치 비교, 실제 경과시간에 의한 지속 조건, 복귀 히스테리시스, 래치, 운전 조건의 3값 논리를 구현했다. 래치 상태에서 결측이 되면 기존 경보를 유지하면서 입력 품질을 UNKNOWN으로 표시한다.
- RATE와 호스 재고 변화를 보정하는 BALANCE를 지원한다. 서로 다른 시점·불량 데이터가 포함된 이력으로 정상 판정을 만들지 않는다. 문자열 식은 제한된 파서로 처리하며 Python eval을 사용하지 않는다.
- 센서 ID를 지정한 편향/고정 고장 주입을 진단 채널에 연결했다. 기존 집계 PLC 고장과 구분하며 이 진단 DB가 물리 PLC를 조작하지 않는다.
- 노드·케이스 단위로 중복 경보를 묶되 서로 다른 GD 위치는 합치지 않는다.

## HyRAM 연결의 의미와 남은 입력

임계값 초과만으로 누출구경이나 질량유량을 확정할 수 없으므로 자동으로 가짜 누출을 만들지 않는다. 사고 후보는 `NEEDS_RELEASE_INPUTS`로 표시한다. 실제 시뮬레이션 누출이 해당 케이스의 후보 노드에 존재하면 기존 HyRAM 계산 결과를 연결한다. 캐시 여부·계산 시각·누출원 압력/온도·구경을 함께 제공한다.

- `RESULT_LINKED`: 해당 누출에 계산 결과 있음. 현장 검증 완료를 의미하지 않는다.
- `PARTIAL_RESULT`: 일부 누출 계산 실패 또는 실내 enclosure 미설정 등 미계산 항목 있음.
- `BACKEND_UNAVAILABLE`: 누출은 있지만 계산 결과 없음.
- `NOT_APPLICABLE`: 해당 진단 규칙은 직접 누출 영향계산 대상 아님.

필수 보완: 실제 누출원 후보 선택, 구경/유효 단면적 및 방출계수, 누출 방향·높이, 지속시간/차단·재고, 주변 조건, 관측점, 실내 체적·환기·개구부, 점화 분기. 3D 시각 배치가 이 입력에 자동 반영되지는 않는다. HyRAM 입력 시트의 요구사항을 따른다.

현재 결과의 `geometry_status`는 SCENARIO_DEFAULTS_NOT_SITE_VALIDATED이다. native HyRAM 시험에서 초크 유동에 대해 전달한 mdot 지정값을 무시하고 내부 초크 계산을 사용한다는 경고가 관찰됐다. 트윈의 재고 감소 유량과 HyRAM 방출 유량의 일치 검증이 필요하다. 위치별 GD 농도가 향후 들어오더라도 다중 누출의 최대값 선택은 중첩 확산 모델이 아니므로 별도 검증해야 한다.

## 실행 및 조회

프로젝트 루트에서 서버 실행:

```powershell
& .\scripts\start_hazop.ps1
```

브라우저 `http://127.0.0.1:8000` → 센서 진단 시험 → `1번 차량 압력계 +90 MPa` → 실행. 물리 탱크값과 편향된 진단값은 다르다. 기본 `없음`은 정상 계측 경로이다.

엑셀 수정 후 재이관 및 매핑 재생성:

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
& .venv\Scripts\python.exe -m h2station.hazop import .\data\hazop-source\HRS_센서기반_HAZOP_DB_v1.0.xlsx
& .venv\Scripts\python.exe scripts\export_hazop_mapping.py
```

재이관은 스키마/참조/수치/식 검증 후 정의 DB를 교체한다. 새 실행부터 적용되며 이미 실행 중인 모니터는 시작 시 읽은 버전을 유지한다. 환경변수 `H2STATION_HAZOP_DB`, `H2STATION_HAZOP_EVENTS_DB`로 저장 위치를 지정할 수 있다.

| API | 용도 |
|---|---|
| GET /api/hazop/catalog | 전체 원본 정의 |
| GET /api/hazop/mapping | 센서 바인딩과 규칙별 부족 사항 |
| GET /api/simulations/{job_id}/hazop | 최신 전체 규칙·신호·모드 진단 |
| GET /api/hazop/runs/{run_id}/events | 재시작 후에도 조회 가능한 이벤트 |
| GET /api/simulations/{job_id}/result | 기존 결과 + HAZOP 프레임·메타데이터 |
| POST /api/simulations/{job_id}/stop | `continuous=true` 가상 모니터링 정지 |

`POST /api/simulations`의 `continuous=true`는 `duration_s`를 반복 solver 창 길이로 해석한다. WebSocket 프레임에는 `analysis`, `gas_detectors`, `released_mass_kg`, `peak_vehicle_temperature_c`가 포함된다.

수동 리셋은 현재 RuleEngine의 reset_requests 인터페이스에서만 지원하며 화면/API는 제공하지 않는다. 새 시뮬레이션은 새 진단 상태로 시작한다. 기존 job 결과는 메모리 기반으로 서버 재시작 시 소멸하지만 이벤트 DB는 유지된다.

## 사고 주입 리모콘과 공정 영향

사고·운전 조작은 메인 모니터에서 제거하고 `/remote.html` 리모콘으로 분리했다. 리모콘에서 여러 사고를 시간 순서로 등록한 뒤 실행하면 메인 화면(`/?job=<job_id>`)은 공정 상태·추세·3D 상태만 표시한다.

구현된 물리 주입은 다음과 같다.

- `pressure-disturbance`: 선택한 뱅크·호스·차량탱크의 현재 EOS 압력에 대한 목표 편차를 질량 유입·유출로 바꾼다. 응답시간 동안 질량과 엔탈피가 상태방정식에 들어가므로 압력·온도·유량이 함께 변한다.
- `temperature-disturbance`: 지정 열원온도와 UA의 열전달을 벽·쉘에 적용한다. 벽→가스 전도와 외기 방열은 기존 열용량 모델을 통과한다.
- `external-fire`: 차량·호스·저장뱅크·압축기 프록시·냉각기 위치에 화염·연기·점광원을 만들고 `UA × (T_fire − T_wall)`로 실제 열을 공급한다. 3D는 색상 장식이 아니라 활성 사고 시각화 상태와 연결된다.
- `hydrogen-leak`: HyRAM 누출 모델의 질량유량을 해당 호스·차량·뱅크 상태의 질량과 내부에너지에서 차감한다. 누출 누적질량과 순간 유량은 결과에 저장한다. 큰 구경도 음의 재고가 되지 않도록 가용 질량으로 제한한다.
- `pipe-restriction`: PCV·노즐·호스의 유효 유동면적 배율을 바꾼다. `check-valve-failure`는 실제 압력차가 반전될 때 역류를 허용한다. 두 디스펜서 노즐(`FT-1301`, `FT-1701`), 유한 공통 헤더의 뱅크 경로(`FT-0701`, `FT-0801`, `FT-0901`), 정지 압축기-트레일러 공통 경로(`FT-0201`~`FT-0601`)는 역류 질량 이동을 계산한다. 압축기 6개 FT는 중간 라인팩이 없는 준정상 공통 유량이며 독립 계측값이 아니다. `FT-2001` 음수는 명시적 벤트 체크밸브 고장에 의한 외기 경계 유입으로, 수소 재고를 증가시키지 않는다. 등가 고장면적은 시나리오 입력이며 외부 보정값이 아니다.
- `pcv-seat-leak`: 1번 또는 2번 PCV의 폐쇄 명령을 유지한 채 선택한 유효 개방률만큼 내부누설을 계산한다. 입력이 0이면 3%를 사용한다. 두 라인의 유량과 HAZOP 격리 실패 판정은 독립이며, `pcv` 대상은 기존 시나리오 호환을 위해 두 라인에 공통 적용한다.
- 기존 PCV 고착, 뱅크밸브 고착, 예냉 상실, 압축기 정지, ESD 요청, 센서 편향·고정도 리모콘에서 선택할 수 있다. 센서 고장은 진단 채널이며 물리 PLC를 직접 조작하지 않는다.

리모콘의 사고 위치는 저·중·고압 저장뱅크, 공통 헤더, 두 충전호스, 두 차량탱크, 두 PCV, 압축기, 차량 압력센서, 예냉 온도센서다. 공통 헤더는 별도 재고를 사용한다. 압축기는 아직 별도 가스 재고가 없어 고압 뱅크를 연결 체적 프록시로 사용하며, 이 한계는 결과 메타데이터와 코드 주석에 남긴다.

각 결과 프레임의 `active_faults`, `total_leak_flow_g_s`, 압력·온도·SOC·뱅크 압력, `faults` 메타데이터를 이용하면 사고 전후 공정 영향을 직접 비교할 수 있다. `external-fire`는 3D 배지에 “사고 시각화”로 표시되고 해당 위치에 화염·연기·열원 점광원이 표시된다. 3D 배치와 사고 위치는 여전히 현장 좌표 승인 도면이 아니다.
최종 결과의 `impact`에는 차량별 최고·최저 압력, 최고 온도, 최대 누출 유량, 누출 누적질량, ESD 시각, 사고 대상 목록을 별도로 저장한다.

## 검증

전용 테스트 20건은 모두 통과했다. 임계값 경계, 0 값, 정확한 지속시간, 히스테리시스/래치, 결측·NaN·품질·단위·시각, 3값 모드, 안전한 식 파서, 이력 변화율/재고 보정, DB-tag 고장 주입, HyRAM 결과/부분 결과 연결, API/WebSocket/영구 이벤트, 압력 교란·열전달 화재·물리 누출 재고 감소를 검사했다. 전체 회귀시험 결과는 26건 통과, 기존 물성 시험 1건 실패이다.

브라우저 10초 시험에서는 PT-1401=95.596 MPa_abs가 87.5 MPa 상한을 넘으며 N14 TRIP 후보와 HyRAM 입력 대기가 표시됐다. 기존 물리 PLC의 충전은 유지됐다. 따라서 진단 채널 연결과 기존 제어 경로의 분리도 확인했다.

전체 회귀시험에서 기존 `test_coolprop_rho_u_round_trip`의 35 MPa 왕복변환 허용오차 검사가 실패했다(계산 35,010,901.216 Pa, 목표 35,000,000 Pa, 허용 약 0.35 Pa). 해당 물성/테이블 코드는 변경하지 않았다. 이 오차는 별도 물성 정확도 검증 과제로 남긴다. 최종 테스트 결과는 `data/hazop-review/validation.txt`에 저장한다.

## 가상 모니터링 화면과 CCTV

메인 모니터는 데스크톱 한 화면을 기준으로 KPI·축약 HAZOP·사고 영향·실시간 분석을 배치하고 3D 화면 높이를 줄였다. 3D 헤더의 `3D / 공정 흐름` 전환 버튼은 같은 상태 스트림을 유지한 채 공간 화면과 공정 흐름도를 교체한다. 공정 블록과 3D 설비를 클릭하면 선택 구역의 가상 CCTV 카드가 열리며 `web/assets/cctv/normal.png`, `leak.png`, `fire.png`는 정상·누출·화재 상태별 ImageGen 자산이다.

리모콘의 `무제한 가상 모니터링`을 켜면 `continuous=true`로 유한 solver 창을 이어 붙인다. 각 창은 이전 `FullStationState`를 다음 창의 초기 상태로 넘기고 HAZOP 시각은 단조 증가한다. `/api/simulations/{job_id}/stop`으로 정지할 때까지 프레임을 계속 WebSocket으로 전송하며, 메모리는 최근 12,000프레임 링 버퍼로 제한한다. 메인 화면의 `모니터 중지`는 해당 API를 호출한다.

각 프레임의 `analysis`는 차량 압력·온도, 누출유량, ESD, 가스검지기 농도를 함께 평가해 `NORMAL / ADVISORY / WARNING / CRITICAL`과 원인·권고를 표출한다. `gas_detectors`에는 태그·구역·vol%·품질·출처가 들어가며, `VIRTUAL_DETECTOR_PROXY` 값으로 HAZOP 경보 후보와 3D 사고 배지를 연동한다. HyRAM 영향 결과는 프레임의 분석 상태와 별도로 결과의 `impact` 및 `risk_updates`에 저장되므로, 사고 위치가 주어진 경우 영향평가가 필요하다는 운영 판단을 화면에 유도한다.
